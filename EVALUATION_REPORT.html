ICD-10-CM Entity Evaluation Report

86,827 diagnostic titles · 3-layer validation · 4 entities compared · April 2026

1 The Problem

We build XML entities to match ICD-10-CM diagnostic classification titles in free text. The Eduction matching engine uses flat headword entries and regex patterns. The ICD-10-CM 2026 dataset contains 86,827 official titles (excluding external cause codes V00–Y99).

A naive entity that composes condition nouns with anatomy terms via patterns like [condition] of [anatomy] produces ~3.7 million possible combinations against only 86,827 real titles — a 43:1 ratio of nonsense to real matches.

False positive examples: "fracture of liver" (fractures are skeletal), "cataract of knee" (cataracts are ocular), "hernia of cornea" (hernias occur in body cavities), "burn of femur" (burns affect surfaces, not bone). These are the dominant output of unconstrained pattern composition.

2 The Four Entities

Original medical_conditions.xml

  • Pre-existing healthcare entity: 13 private sub-entities
  • 12,577 flat entries (conditions, anatomy, adjectives, roots, prefixes)
  • General-purpose medical vocabulary — not ICD-10-CM-specific
  • No compound patterns in public entity — matches each sub-entity independently
  • 629 KB — compact, hand-curated

Baseline (ICD-derived, unconstrained)

  • Built from ICD-10-CM CSV with unconstrained compound patterns
  • 14,085 flat entries + 67 compound patterns
  • [condition] of [anatomy] allows any condition with any anatomy
  • 80 score=0 FP suppression patterns
  • 936 KB

Strategy 1: Domain-Split Compound Patterns

  • Anatomy split into 8 domain-specific sub-entities
  • Compound patterns constrained: only valid condition+anatomy pairings
  • All titles as flat entries + abbreviation variants
  • Short entries (≤2 words) anchored with ^entry$
  • 12,094 KB — large due to full entry set + compound patterns

Strategy 3: Flat Entries Only

  • Every title listed explicitly — zero compound patterns
  • Encounter suffixes factored out; abbreviation variants generated
  • Short entries (≤2 words) anchored with ^entry$
  • No FP suppression patterns needed — nothing to suppress
  • 4,566 KB

3 Evaluation Architecture

Three independent validation layers, ordered by increasing resistance to overfitting.

1
Development FP Dataset — 846 entries (600 TP, 234 FP, 12 edge)

Hand-crafted. 7 FP categories: impossible_combo, domain_mismatch, common_english, partial_medical, ambiguous_short, near_miss, nonmedical_text (63 entries from news, legal, finance, tech, sports, cooking, etc.). Visible to builders. fp_dataset.json

2
Static Validation Dataset — 957 entries (300 TP, 657 FP)

Programmatically generated: cross-domain swaps, random combos, template remixes, novel English, boundary probes. All FPs verified against 445K-term ICD dataset. fp_validation.json

3
Adversarial Validation — ~740 entries generated dynamically

Extracts vocabulary from the entity's own headwords at eval time. Generates vocab_recombination (300), word_soup (100), affix_probe (60), context_injection (80). No static file. Unforgeable.

Why Layer 3 cannot be gamed. The entity itself is the input to FP generation. If "glaucoma" and "kidney" are both matchable, the adversarial layer tests "glaucoma of kidney". 0/300 vocab_recombination means the structural combination problem is solved. 0/100 word_soup means substring pollution is solved.

Composite score formula

Composite = Coverage × 0.35 + (100 − Dev FP) × 0.15 + (100 − Val FP) × 0.15 + (100 − Adv FP) × 0.25 + Size × 0.10
Size score = max(0, 100 − file_size_KB / 50)

Adversarial FP rate carries the highest weight (25%) because it is the only metric that cannot be gamed.

5.4 — False positive breakdown

All FP matches in the original entity occur via flat_substring — a short flat entry appearing as a substring in the test phrase. The entity has no compound patterns generating novel combinations; the problem is that individual medical words match indiscriminately.

The core flaw: vocabulary without constraints. The original entity stores individual medical words (“fracture”, “liver”, “chronic”, “hyper”) as flat headwords. Any text containing one of these words as a ≥5-character substring matches. There is no mechanism to distinguish “fracture of femur” (real ICD title) from “fracture of liver” (impossible), “viral pneumonia” (real) from “viral video” (common English), or “hypothermia” (real) from “hyperplaxitis” (fake word).

5.5 — Original vs. Baseline vs. Strategies

The original entity and the ICD baseline score almost identically (~48 composite) despite fundamentally different designs. This is because they share the same structural flaw:

PropertyOriginalBaselineStrategy 1Strategy 3
Single-word flat entries Yes — thousands Yes — thousands No — anchored with ^...$ No — anchored with ^...$
Condition+anatomy constraints None None (any × any) 8 domain sub-entities N/A (no compound patterns)
Common English rejection No filtering 80 score=0 patterns Structural (no short entries match) Structural (no short entries match)
Vocab recombination FP 286 / 300 (95%) 290 / 300 (97%) 0 / 300 0 / 300

The baseline adds compound patterns that push coverage from 92% to 99.5%, but makes the FP problem worse (88% vs 74% dev FP) because those patterns create a combinatorial explosion. Both are effectively vocabularies without grammar — they know the words of medicine but not the rules for combining them.

Outcome

The original entity and the baseline score nearly identically (~48) because both share the same structural flaw: individual medical words as flat entries match indiscriminately. The ICD-specific strategies solve this by (1) constraining compound patterns to valid domains (S1) or abandoning them entirely (S3), and (2) anchoring short entries to prevent substring matches. This yields a ~2× improvement in composite score.

10 Known Limitations

LimitationImpact
Simulation vs. real engine Evaluator uses substring matching (more permissive than Eduction's phrase-boundary matching). FP rates are conservative upper bounds.
Context injection "Patient denies fracture of femur" contains a real title. 76/80 matched. Reported separately, excluded from FP rate.
7 residual static FPs 3+ word entries ("fracture of femur", "laceration of stomach") substring-match into phrases like "old fracture of femur". Most contain real diagnoses. Irreducible floor of substring matching.
Natural variant TP misses 63 reordered/abbreviated variants missed. These require word-order-flexible matching.
Original entity evaluation The original has no public entity; we wrapped it. Some commented-out compound patterns (cross-references between sub-entities) were not activated — in production these would change behavior.
Cross-reference opacity (?A:...) patterns are not evaluated by the simulator. Strategy 1's compound patterns are tested only via overlapping flat entries.
